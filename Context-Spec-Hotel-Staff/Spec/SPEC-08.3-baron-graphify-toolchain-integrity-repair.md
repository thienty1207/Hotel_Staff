## 8. Root-fix decision order

Determine the exact Baron contract, including commands, argument ordering,
output path, `graph.json` location, query output schema, and capability
response. Resolve the issue in this order:

1. A supported Baron version compatible with current Graphify.
2. A supported Graphify version compatible with installed Baron.
3. An official Baron provider-adapter mechanism, if explicitly supported.
4. A durable adapter only when the conditions in section 9 are all proven.

Do not blindly run the public/unsafe `baron update` path or perform an
undocumented destructive global upgrade.

## 9. Adapter restrictions

An adapter is allowed only if Baron officially supports custom CLI providers,
no compatible native pairing exists, behavior is deterministic and
version-controlled, automated tests cover it, a supported Graphify range is
explicit, it translates invocation/output only without fabricating semantic
results, normal Graphify remains independently usable, and Baron capability
check recognizes it legitimately.

If any condition is unproven, do not implement an adapter. The temporary
`.baron/tmp/graphify-compat/` experiment is never an acceptable final provider.
